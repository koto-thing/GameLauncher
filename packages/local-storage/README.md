# Local storage

PublisherとLauncherのローカルファイル操作を共有するRust crateです。

- 管理rootを固定し、相対パスの逸脱・symlink・Windows reparse pointを拒否
- 削除対象全体を事前検査し、指定されたファイル／ディレクトリだけを削除
- 一時ファイルへの書き込み・同期・renameによるJSONの原子的保存
- ディレクトリの退避・切り替えと、確定処理が失敗した場合の復旧

Launcherの配置ポリシーは`apps/launcher/rust/src/installation.rs`にあります。
検証済みstagingをreleaseへ移動してactive.jsonを確定します。
同一版の既存ディレクトリは先にtrashへ退避し、確定失敗時には新しい版をstagingへ戻して旧版を復元します。
復旧自体が失敗した場合はバックアップを削除せず、エラーに場所を記録します。

確定後の清掃は現行版と切り替え前の有効版を保持します。
同一版の修復では、現行版より小さい最大のバージョンも保持します。
清掃失敗は警告として記録し、既に確定したインストールを失敗扱いにしません。
一時データ整理はactive markerと実際のreleaseを確認してstaging/cacheのみを削除します。
復旧用バックアップが残っている場合は整理を拒否します。

PublisherはJSON保存とローカルGCの削除境界を共有します。
配信物の保持期間・参照チャンク判定・R2削除はPublisher固有のポリシーとして分離しています。

復旧は処理中に返されたエラーに対するものです。複数のrenameを電源断に対して一括で原子的にする仕組みや、
強制終了後の自動復旧はありません。未解決のbackupは自動で上書き・削除せず、その場所をエラーで通知します。
同じrootへの変更は呼び出し元が直列化してください。パスの事前検査は同一権限の別プロセスとの競合を隔離するものではありません。

`cargo test --workspace --locked`で確定失敗、復旧失敗、保持ルール、削除範囲を検証します。
