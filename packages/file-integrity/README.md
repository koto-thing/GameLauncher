# File integrity

PublisherとLauncherで共有するファイルI/O用Rust crateです。配布マニフェストの型やネットワーク処理から独立しています。

- SHA-256のストリーミング計算とサイズ・ハッシュ検証
- Publisherのチャンク分割と全体ハッシュ計算（元ファイルは1回読み取り）
- チャンクと全体ハッシュを結合中に検証する原子的なファイル生成
- コピー中の検証と、既存ファイルの指定範囲からのチャンク復元

結合・取り込みは1 MiBのバッファで読み取り、同じバイト列を検証して一時ファイルへ書き込みます。
検証後に同期・renameして確定し、不一致やキャンセルでは既存の出力を保持します。
出力ファイルを検証目的で再読み込みする処理はありません。
親ディレクトリの信頼性・パス制約は呼び出し側が検証します。入力の末端symlink/reparse pointはcrateでも拒否します。

| 処理 | 変更前 | 変更後 |
|---|---|---|
| 取得済みチャンクの結合段階 | チャンク検証 + 結合用読み取り + 出力の再検証 | 各チャンクを1回読み、両方のハッシュを計算 |
| 既存ゲームの取り込み | 元ファイル検証 + コピー + 出力の再検証 | 元ファイルを1回読み、コピー中に検証 |
| 修復時のキャッシュ判定 | 再利用時と取得一覧作成時に再検証 | 同一操作内で検証結果を保持 |

ダウンロード完了時の検証と、結合時の実データ検証は両方行います。
変更可能なキャッシュを過去の検証結果だけで結合しないためです。
読み込み回数はアルゴリズム上の比較であり、OSの物理ディスクアクセス回数や実行時間の測定値ではありません。

`cargo test --workspace --locked`で破損、サイズ不一致、キャンセル、書き込み失敗とPublisher→結合の往復を検証します。
