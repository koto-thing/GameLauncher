## 単体・API統合で確認した範囲

- ループ境界、有限値、再生位置、シーク、キュー末尾、リピート、シャッフル、設定値と権限の検証。
- 未認証、CSRF不一致、別作品ID・別作品Assetの差し込み、担当解除後の既存セッション、運営限定操作の拒否。
- 担当者だけで登録・公開・更新・非公開化が成立すること。下書き編集が公開中の音源・ループ・曲順へ漏れず、競合は409になること。
- 本物のD1クエリー、R2オブジェクト、HTTP upload / 配信を通した検証。公開DTOへの下書き・内部キー漏れ、非公開・停止中Assetの直接取得を拒否。
- Range / HEAD / 416、MP3・WAVの解析、PNG・JPEG・WebPの実データ検証、不正HTML・SVG・切断素材の拒否、失敗後の再登録。
- 広告権限とOFF、回数制限、logout、stateの単回使用とPKCE、本番Workerにローカルログイン入口が存在しないこと。

OAuth統合テストでは外部プロバイダーの交換処理をテスト実装に差し替えています。GitHubとの実際のコールバック往復やアカウント設定の合格を意味しません。

## ブラウザーと音声で確認した範囲

- 360 / 390 / 430 / 1280px、作品・曲の直接URL、縦長画像の全体表示、自動再生なし、画面遷移、ブラウザーエラーなし。390pxのスクリーンショットを目視確認しました。
- 通常再生、区間ループ、区間中の一時停止・再開、区間外シークの補正、遷移中の再生維持、ループ解除から次曲への遷移。
- 同じAudioEngineでループ準備中の曲変更、デコード済み曲の8回切替、古い準備処理の無効化、AudioContext suspend / resume、低メモリ予算での明示エラーと通常再生への復帰。
- 実装と共通のAudioBufferSourceNodeスケジューリング関数をOfflineAudioContextでレンダー。イントロ1回とループ10回について、24kHz・23秒・552,000サンプルを期待波形と比較し、最大絶対誤差が1e-6未満（Chromium / Firefox）。これは波形比較であり、実機出力の聴感評価ではありません。
- 担当者UIから音源・画像・クレジット登録、保存、ループ設定、継ぎ目試聴、承認なしの公開、公開APIへの反映、未保存遷移のキャンセル。
- 広告API障害が再生を妨げないこと。Web Audio APIがない場合に理由を表示し、ループをOFFに戻して通常再生を再試行できること。

Windows版WebKitはこの環境でAudioContext / OfflineAudioContextを提供しません。音声競合・ライブ区間ループ・オフライン波形の3件をスキップし、投稿フロー内の継ぎ目試聴も未検証として注記しています。メタデータの保存・公開と非対応時の復旧は検証済みです。iOS Safariの可否はこの結果から判断していません。
