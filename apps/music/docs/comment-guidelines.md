# コメント規則

TypeScript/JavaScriptの意味のある処理のまとまりに、日本語の `//` コメントを付けます。入力検証、認可、競合、公開状態切替、副作用、非同期結果の無効化、エラー・後片付けについて「なぜ必要か」を説明してください。`// if文` のような構文の言い換えは避けます。

自作関数、メソッド、コンストラクター、Reactコンポーネント、Hook、匿名callback、テスト、運用スクリプトに `/** @brief ... */` を付けます。単位、引数、戻り値、失敗条件が利用者に必要な関数では `@param`、`@returns`、`@throws`、`@remarks` を追記します。存在しない引数等のタグは追加しません。

```ts
/**
 * @brief 音源内の現在位置を保存し、準備中の旧処理を無効化する。
 * @remarks 音声Nodeは再利用できないため再開時は新しく作る。
 */
function pause(): void {
  // 停止する前の音声クロック位置を保持し、再開時のずれを防ぐ。
  savePosition();
  stopSource();
}
```

JSXの中は `{/* ... */}`、CSSは `/* ... */`、SQLは `--` を使います。外部依存と `wrangler types` の生成物は対象外です。

`npm run lint` は関数ドキュメントと依存方向の検査を含みます。ただしコメントの意味と十分さはコードレビューでも確認してください。機械検査だけを説明の品質保証にはしません。
