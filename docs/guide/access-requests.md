# 利用申請と権限管理

管理サイトの `/access` から、GitHubの数値IDを調べずに利用を申請できます。
トップページ、ゲーム管理のログイン案内、Music管理の「利用申請・審査」から開けます。

## 利用者の操作

1. GitHubでログインします。
2. 「利用申請」でGameLauncherまたはMusicを選びます。
3. 氏名・活動名、利用目的を入力します。Musicは担当したい作品名も入力します。
4. 「利用を申請する」を押します。
5. 「状態を更新」で審査状況を確認します。承認後は「管理画面を開く」へ進みます。

申請者のGitHub本人情報はログインから取得します。入力した氏名・活動名は審査の参考情報であり、本人確認や権限判定には使いません。
同じ対象への承認待ち申請は一つです。却下理由を確認した後に再申請できます。
承認履歴は取消後も残るため、現在の権限は各管理画面で確認してください。

## 運営の操作

`/access` でサービスを選び「申請を審査する」を開きます。申請者のプロフィールと利用目的を確認し、付与する権限または作品を選んで承認します。却下には理由が必要です。

- GameLauncherはリポジトリOwnerが審査します。既存の申請者・承認者・本番申請者のいずれかを付与します。
- GameLauncherでは承認時にGitHub Appで申請者の最新のWrite以上のリポジトリ権限を確認します。権限不足ならGitHub側で設定した後に再承認します。
- Musicは明示登録されたMusic運営だけが審査します。申請の作品名を確認して、実際の作品を選びます。未公開の作品一覧は運営にだけ表示します。
- 自分の申請は審査できません。申請によって管理者権限を付与する機能はありません。

承認と権限付与はD1の同一batchで確定します。同時審査は一件だけが成功し、失敗した保存は審査状態も権限も巻き戻ります。
審査者、時刻、付与範囲、却下理由は `access_requests` に残ります。Musicの付与は既存の監査ログにも記録します。

登録済み利用者の追加権限と取消は、従来のゲーム管理・Music運営設定から名前で選んで操作します。未登録の数値IDを入力して本人を作成する経路はありません。

## 設定と公開前確認

既存の共通GitHub OAuth、SESSION_SECRET、D1を使用します。GameLauncherの承認時照会には既存の `GITHUB_APP_ID`、`GITHUB_APP_INSTALLATION_ID`、`GITHUB_APP_PRIVATE_KEY` と対象リポジトリのMetadata read権限が必要です。照会用トークンはMetadata readに限定し、Actionsのdispatch有効・無効設定とは独立します。

Musicの申請・審査は `MUSIC_ENABLED=true` の環境のみ有効です。Music運営の初期登録方法は変更しません。
申請用テーブルと索引は既存の `ensureSchema` によって追加されます。既存のユーザー・権限データの移行や削除は不要です。

申請・審査には同一originと15分以内の本人確認が必要です。期限を過ぎた場合はGitHubで再ログインしてください。
本番公開前に実GitHub Appの資格情報と、対象者のリポジトリ権限照会を確認してください。
