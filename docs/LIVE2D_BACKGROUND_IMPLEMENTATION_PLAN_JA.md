# ゲーム詳細画面のLive2D背景 実装計画

作成日: 2026-08-26

状態: 実装済み（2026-08-27）。この文書は当初の設計記録。現在の手順・検証結果は
[LIVE2D_BACKGROUNDS_JA.md](LIVE2D_BACKGROUNDS_JA.md) を参照。

決定事項（2026-08-26）: Windowsのローカル開発とCIはMSVC 2022 x64へ統一する。
同梱モデル方式と公式SDK取得方式で実装。本番モデルの登録と公開許諾の確認は未実施。

## 1. 目的と今回の範囲

ゲーム一覧で作品を選択した後の詳細画面に、そのゲームに対応するLive2Dモデルを表示する。
現在の背景画像を舞台として残し、その上にモデル、読みやすさを保つ暗幕、既存の操作UIを重ねる。
詳細画面を共有する「トップ」「さがす」からの遷移にも同じ表示を適用する。

初回実装の提案範囲:

- 画面内に1体。ゲームごとにモデル、配置、表示倍率、待機モーショングループを指定する。
- モデルが備える待機モーション、まばたき、呼吸、物理演算を再生する。
- 背景用の表示とし、クリックやキーボードフォーカスは既存UIに渡す。
- 非表示、最小化、トレイ格納、ゲーム実行中はアニメーションを停止する。
- モデル素材はランチャーに同梱し、ランチャーの通常更新で配布する。

対象外: 任意モデルのユーザー取り込み、モデル専用のオンライン配信、複数体同時表示、
タップ反応、視線追従、音声・リップシンク、表情切り替えUI。
これらは要求が発生した場合に別途設計し、今回の実装に予備の拡張機構を作らない。

| SDK | 指定先にCore、Framework、OpenGLサンプル、モデル素材が存在 | サンプル一式ではなく必要なSDK部分を利用 |

これは「MinGWでは絶対に動かない」という検証結果ではない。今回はMinGWとの連携層を追加せず、
Windowsローカル開発も既存CIと同じMSVC 2022 x64へ統一する。

## 3. 推奨する構成

### 3.1 描画方式

**QtのQOpenGLWidgetと、Cubism Native FrameworkのOpenGLレンダラを使用する。**

表示の順序は次の通り。

```text
ゲーム詳細画面
  背景描画領域（QOpenGLWidget）
    1. 背景色・既存hero画像
    2. Live2Dモデル
    3. 文字を読みやすくするグラデーション
  前面のQt Widgets
    戻る / 設定 / タイトル / 説明 / お知らせ / 進捗 / 起動ボタン
```

透明なOpenGLウィジェットを既存の画像ウィジェットに重ねる方法は採用しない。
Qt公式資料の重なり順の制約を踏まえ、画像とモデルを同じ描画面に合成し、操作UIを上に置く。
DirectX版やWeb版の別実装、自動バックエンド切り替えは追加しない。
参考: [QOpenGLWidget公式ドキュメント](https://doc.qt.io/qt-6/qopenglwidget.html)。

画像読込には既存のQt画像処理、時刻管理にはQElapsedTimer、更新要求にはQTimerを使う。
CubismのデスクトップOpenGL実装が依存するGLEWはvcpkgで管理する。
ウィンドウやイベントループはQtが管理するためGLFWは不要。画像読込用のstbも追加しない。

### 3.2 責務の分離

以下は追加・分離するファイルの候補。SDKをドメイン層やインストール処理に持ち込まない。

| コンポーネント | 責務 |
| --- | --- |
| `presentation/GameDetailPage` | 背景と既存UIの配置。LauncherWindow内のHeroPageを置き換える |
| `presentation/Live2DBackgroundWidget` | OpenGLコンテキスト、背景合成、画面サイズ、再描画、描画停止 |
| `presentation/live2d/CubismRuntime` | SDKの初期化・終了、アロケータ、ログ、ファイル読込コールバック |
| `presentation/live2d/Live2DModel` | model3.jsonと参照素材の読込、モデル更新、モーション、Cubismレンダラの所有 |
| `presentation/live2d/Live2DAssetCatalog` | 同梱設定からgameIdに対応する素材と配置を解決・検証 |

Runtimeはアプリ内で一度初期化し、全モデルとGPU資源の破棄後に終了する。
SDK依存の実装は専用ライブラリターゲットにまとめ、QtのUIヘッダへ不要なSDK/GLEWヘッダを露出させない。
旧HeroPageの描画実装を互換用に残したり、並行して保守したりしない。

### 3.3 モデルの登録と配布

同梱設定を `apps/launcher/resources/live2d/models.json` に置く案とする。
登録単位は `gameId`、モデルの相対パス、正規化した配置座標、倍率、待機モーショングループのみ。
未登録のゲームはモデルなしという正式な表示状態とし、hero画像を表示する。

素材は `.model3.json` を入口に、`.moc3`、テクスチャ、指定されたmotion3/physics3等を一式で管理する。
元のディレクトリ構造を維持し、不要な音声など今回使用しない素材は配布対象に含めない。
ゲーム本体のインストール先には依存させず、未インストールのゲームでも表示可能にする。

ランチャー同梱は今回の正式な配布方式とする。モデルを変更するにはランチャー更新が必要になる。
「モデルを運営画面から随時差し替える」ことが必須なら、実装開始前に配布方式を再決定する。
その場合は署名・ハッシュ検証、容量制限、取得中断、キャッシュ、公開ツールまで別の作業範囲になる。

### 3.4 SDKの取り込みと再現可能なビルド

- CMakeに `PANDD_CUBISM_SDK_ROOT` を追加。ローカルでは指定されたディレクトリを渡す。絶対パスはソースや共有presetへ固定しない。
- WindowsはMSVC 2022 x64と対応するQt/OpenSSL/GLEWを使用。Coreは動的CRT用のMD/MDd静的ライブラリとビルド種別を一致させる。
- FrameworkのOpenGL部分のみを組み込み、SDKのサンプルCMake全体は取り込まない。
- macOS/Linuxも対応するCoreとコンパイル定義を選び、同じ描画実装をビルドする。macOSのOpenGL制約、LinuxのGL環境は実機検証項目にする。
- SDK不足や未対応ツールチェーンはconfigureで明示的に失敗させる。知らないうちにLive2Dを外した成果物は生成しない。
- CIでは公式配布元からの取得を第一候補とし、自動取得方法と利用条件を確認した上で版とSHA-256を固定する。SDKの独自保管は必須ではなく、SDKを無断で公開リポジトリに追加しない。
- Qt OpenGLモジュール、Core、Framework、GLEWをビルドメタデータ・SBOM・ライセンス収集へ反映する。

SDKのOpenGLシェーダーは外部ファイルで、Frameworkが `FrameworkShaders/...` を読み込む。
今回の版には `CubismFramework::Option` の `LoadFileFunction` / `ReleaseBytesFunction` が存在する。
この入口でQtリソースへ解決し、起動時のカレントディレクトリに依存させない。
シェーダーと許諾済みモデルをQtリソースに含めることで、アプリと素材の版を揃える。

### 3.5 GitHub ActionsでのSDK準備

既存のWindows WorkflowはMSVC用Qtの導入、MSVC環境の初期化、vcpkg、CMakeによるビルドを実施している。
ここにCubism SDKの取得・展開・検証を追加する。開発PCのSDKディレクトリはGitHubのrunnerから参照できない。

1. 既存手順でMSVC環境と対応Qtを用意する。
2. vcpkgでOpenSSLと追加するGLEWを用意する。
3. 利用条件への同意と自動取得の可否を確認した公式配布元から、固定版SDKアーカイブを取得する。公式取得が運用に適さない場合の認証付き内部保管は、条件を別途確認してから採否を決める。
4. SHA-256を照合してrunner内に展開し、展開先を `PANDD_CUBISM_SDK_ROOT` としてCMakeに渡す。
5. Frameworkをソースからビルドし、Coreのビルド済みライブラリとランチャーをリンクする。
6. テスト、インストーラ作成、既存の配布処理へ進む。

公式GitHubリポジトリだけではCoreは揃わないため、cloneだけでSDK準備完了とは扱わない。
参考: [Live2D公式リポジトリ](https://github.com/Live2D/CubismNativeSamples)、
[公式SDKダウンロード](https://www.live2d.com/sdk/download/native/)。
公式の固定版URL・自動取得手順は未検証であり、実装時に確定する。認証・同意・アクセス制限を迂回しない。
Google Drive等への保管は、認証付き内部保管と公開リンクによるSDK再配布を区別する。
非公開であってもクラウドCIでの利用が契約上許容されると本計画では断定しない。
必要に応じてLive2Dへ確認する。SDKを含むキャッシュやartifactも意図しない第三者アクセスを防ぐ。
参考: [Core使用許諾契約の第3・5・6条](https://www.live2d.com/eula/live2d-proprietary-software-license-agreement_jp.html)。
既存のQt/MSVC/vcpkg用セットアップActionは第三者提供であり、Live2D公式の一括セットアップActionではない。

## 4. 段階的な実装手順と完了条件

### 段階1: ビルド条件の確定と最小描画

1. MSVC 2022 x64 / 対応Qtを準備し、変更前のランチャーと既存CTestが通ることを確認する。
2. SDK・GLEW・Qt OpenGLのCMake統合、SDK版チェック、シェーダー読込を追加する。
3. 本番に残す背景コンポーネントで、検証用モデル1体を描画する。
4. 背景画像・モデル・Qtボタンの合成、マスク、半透明、リサイズを確認する。

完了条件: Debug/Releaseで表示でき、ボタンが操作できる。モデルに黒背景が付かず、
クリッピングが崩れない。SDKディレクトリや作業ディレクトリを実行時に参照しない。
この段階でQtとCubismの描画上の相性を確認してから、モデル登録や演出へ進む。

### 段階2: 実際のゲーム詳細画面への統合

1. HeroPageをGameDetailPageへ分離し、旧実装を置き換える。
2. 既存のhero画像取得・注視点指定を新背景へ接続する。
3. 同梱設定からgameIdに対応するモデルを選び、配置・倍率を反映する。
4. ゲーム切り替え時に前のモデルを破棄し、遅れて完了した読込は選択世代を照合して破棄する。

完了条件: 一覧から選んだゲームのモデルだけが表示される。未登録ゲームは画像だけになる。
同じゲームのデータ更新ではモデルを再ロードしない。ダウンロード・起動・設定の既存操作を維持する。

### 段階3: アニメーションと寿命管理

1. SDKサンプルの更新順を参照し、待機モーション、まばたき、呼吸、物理演算を組み合わせる。
2. 更新は実時間差分を用い、復帰時の差分をリセットして急な飛びや物理演算の暴走を防ぐ。
3. 初期値は30fps上限。詳細ページ表示中かつウィンドウ表示中、ゲーム非実行時だけ更新する。
4. ViewModelのゲーム状態通知とウィンドウ状態を結び、ページ離脱・最小化・トレイ格納・ゲーム起動時にタイマーを停止する。
5. モデルのGPU生成・描画・破棄は有効なQt OpenGLコンテキスト上で実行する。ファイル読込・画像デコードだけをQtConcurrentへ分離する。

完了条件: 不要なときにモデル更新が発生しない。戻る・再選択・復帰・終了を繰り返しても
メモリ/GPU資源が増え続けない。常駐モデルは原則1体とし、複雑なキャッシュは作らない。

### 段階4: 異常系と描画の仕上げ

- モデル設定内の絶対パス、親ディレクトリへの逸脱、不正な数値、欠損参照を検証する。
- SDKのMOC整合性検査を有効にし、ファイル容量・テクスチャ寸法に上限を設ける。
- 必須ファイルの欠損・破損は非モーダルな通知とログで報告し、無限再試行しない。まばたき・物理演算等はモデルが提供する機能だけ使う。
- モデル読込エラーは背景演出のエラーとして扱い、ゲームのインストール状態を変更しない。
- OpenGL初期化失敗を黙殺しない。別の描画APIへの自動切り替えは作らず、通知と他画面への操作が維持できることを検証する。
- Qt管理のフレームバッファを使い、FBO 0固定を避ける。Cubismのマスク描画後にも描画先・viewport・GL状態を確認する。
- GLEWとQtのヘッダ順序、コンテキスト初期化順、premultiplied alpha、テクスチャの上下向き、DPI倍率を検証する。
- SDKのシェーダーに合うOpenGLバージョン・プロファイルを選ぶ。Qtのネイティブ描画との境界でGL状態を適切に管理する。

完了条件: 通常表示に加え、壊れた素材、短時間の連続選択、休止・復帰、高DPIで操作不能にならない。

### 段階5: 配布と受け入れ確認

1. 既存3OS CIのビルドとテストを確認し、Windows staging/releaseにもSDK取得を適用する。
2. SDKシェーダー・モデル・追加Qt依存・ライセンスを含むインストール成果物を作る。
3. SDKや開発ツールのないWindows環境にインストールして実際のモデル描画を確認する。
4. 利用者向け設定説明ではなく、開発者向けにモデル登録・配置調整・更新手順を文書化する。

完了条件: クリーン環境で一覧選択からモデル表示、ゲーム起動まで通る。
Windowsでの受け入れを最初の基準とし、macOS/Linuxの動作確認をせずに対応済みとは記載しない。

## 5. 検証方針

既存のDomain/Integrationテストは継続する。現在の `--smoke-test` はウィンドウを描画する前に終了するため、
その成功だけではLive2Dの検証にならない。

- 素材登録・検証・選択世代・停止条件はGPUを使わないテストで確認する。
- GUI/描画の既存テスト群がないため、必要最小限の専用テストターゲットを追加する。
- 実際にコンテキストを作る描画テストでは、静止した既知モデルを表示し、空描画でないことを確認する。
- offscreenプラットフォームだけでGPU合成の成功とみなさず、GPU利用可能な検証環境と実機確認を分ける。
- 最小サイズ960×600、1280×720、最大化、DPI 100/150/200%、テーマ切替、設定ダイアログ、トレイ復帰を確認する。
- ページ離脱・最小化・ゲーム実行中の更新回数が0であることを確認する。復帰時は通常速度から再開する。
- 連続切替と長時間表示でCPU/GPU使用率・メモリを記録し、採用モデルで30fps以内のフレーム予算を満たすか評価する。
- `cmake --install` した成果物を別の作業ディレクトリから起動し、素材とシェーダーの欠落を検出する。
- SBOM・ライセンス収集・インストーラを変更する場合は既存Pythonテストも実行する。

## 6. 実装前に合意したい事項

| 項目 | 推奨初期値・扱い |
| --- | --- |
| 使用するモデルとゲーム | 対象gameIdとモデル一式を指定。未決定ならSDKサンプルで技術検証のみ実施 |
| 配置 | 既存UIを避けた中央〜右寄せ。実モデルを見て座標・倍率を調整 |
| 配布 | ランチャーに同梱。ゲーム未インストールでも表示可能 |
| Windows開発環境（決定済み） | MSVC 2022 x64に統一。MinGW連携層は追加しない |
| 演出 | 待機・まばたき・呼吸・物理演算。ユーザー入力への反応はなし |

公開前にはSDK利用条件、Core/Frameworkの再配布条件、モデルごとの素材利用条件を確認する。
SDKサンプルがそのまま本番配布可能であるとは扱わない。
また、ランチャーの提供形態がどのライセンス区分に当たるかは本計画では断定しない。
Core使用許諾契約1.5の拡張性アプリケーションの定義には、複数作品へのアクセスを提供するポータルも含まれる。
任意モデル取り込みの有無だけで判断せず、今回のゲームランチャー自体の該当性を公開前にLive2Dへ確認する。
参考: [SDKリリースライセンス](https://www.live2d.com/sdk/license/)、
[拡張性アプリケーション](https://www.live2d.com/sdk/license/expandable/)。

## 7. 調査と未検証の境界

実施済み: 既存ソース・CMake・ローカルCMakeCache・CI構成・SDKファイルと公式資料の確認。

未実施: Cubismのリンク、Qt上でのモデル描画、性能測定、MSVC環境の導入、CI用SDK配置、
モデルの本番利用許諾の確認。描画方式の妥当性は段階1で実測して判断する。
SDK本体と既存の作業中ファイルは変更していない。
